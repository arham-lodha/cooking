# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A personal collection of recipes, weekly meal preps, a cooking log, and grocery tracking (current stock + purchase history). There is no code to build, lint, or test — this is a notes/content repo. Treat requests here as cooking/grocery assistance and file organization, not software engineering.

A separate budgeting file (outside this repo) is planned to eventually connect to the grocery purchase log — not built yet. Don't build that integration until the user brings it up; for now just keep `groceries/PURCHASES.md` entries dated and itemized so it's easy to connect later.

"Meal prep" here means: on one prep day, fully cook a small number of dishes — default 2, alternated across weekdays (e.g. A/B/A/B/A) — so weeknights are pure reheat-and-serve with no assembly. Weekends aren't covered by the weekday plan unless the user asks to include them. A different recipe every day is still an option for weeks with more time or when cooking for more than one person, but the low-effort batch format is the default given limited weekday time.

## Dietary profile (always respect this)

The user is **lacto-vegetarian**: no eggs, no meat, no fish/seafood — dairy is fine. Never suggest or include a recipe with egg, meat, or fish as an ingredient, including as a substitutable default (e.g. don't default to fish sauce — suggest a vegetarian substitute). When adapting a non-vegetarian recipe, note the substitution made.

## Cooking goals

- Ethnically Indian and loves Indian food, but the explicit goal is to **learn a wide variety of cuisines**, not just cook Indian food.
- Favorite cuisines to explore: **Thai, Italian, Mediterranean** (in addition to Indian).
- Actively trying to **improve as a cook** — when helping, prefer explaining technique (why a step matters, common mistakes) over just listing instructions.
- With the default 2-dish weekly format, cuisine variety happens week-to-week rather than within a single week — pick a different cuisine pairing than the prior week rather than trying to fit multiple cuisines into one week's 2 recipes, unless the user asks for a full-variety week.

## Structure & conventions

- `recipes/` — one file per recipe, named `recipes/<cuisine>/<recipe-name>.md` (create a cuisine subfolder as needed). Use `templates/recipe-template.md` as the format.
- `meal-prep/` — one file per week, named `meal-prep/YYYY-MM-DD.md` (Monday of that week). Use `templates/meal-prep-template.md`: a prep-day checklist, a day-by-day table (recipe, what's prepped ahead, day-of assembly/reheat steps, portions), a storage table (fridge/freezer life per component), and a shopping list.
- `cooking-log/LOG.md` — single running log, newest entries at the top. Append an entry every time the user cooks something, whether it's a new recipe or a repeat, so progress over time is visible.
- `groceries/INVENTORY.md` — living document of current stock, grouped by Fridge/Freezer/Pantry, with quantity and use-by date per item. Always reflects what's actually on hand right now — edit rows in place (update quantity, remove when finished, add when new stock arrives) rather than appending a log.
- `groceries/PURCHASES.md` — one entry per shopping trip, newest at the top: date, store, items bought. No cost tracking yet (see budgeting note above).
- `groceries/SHOPPING-LIST.md` — pending items queued for an upcoming trip, grouped by store, as checkboxes. When the user reports the trip happened, move the checked items into a dated `PURCHASES.md` entry, update `INVENTORY.md`, and clear them from this file.
- **Regular stores:** Trader Joe's and Target for routine shopping. 99 Ranch is nearby but only for items the other two don't carry, or urgent needs — don't default to it in shopping lists unless the item is genuinely hard to find elsewhere (e.g. specific Asian ingredients).
- `templates/` — canonical formats for recipes and meal preps. Update these if the user wants to change the format, rather than letting individual files drift.
- `site/` — zero-dependency Node build script (`site/build.js`) that generates a static HTML site into `docs/` for GitHub Pages, covering `meal-prep/` and `groceries/` (recipes and the cooking log are not part of the site yet). Markdown stays the source of truth — never hand-edit files under `docs/`, they are generated output.
- `docs/` — generated site output (GitHub Pages serves this folder from the `main` branch). Regenerated by the build script, not edited directly.

## Workflow expectations

- When the user asks for a meal prep (a week or a single meal), write it into `meal-prep/` following the template — including prep-day checklist, storage/reheat details, and portion counts — and create/link any new recipes into `recipes/`. Check `groceries/INVENTORY.md` first so the shopping list only includes what's actually missing.
- When the user describes a cooking session (what they made, how it went), add an entry to `cooking-log/LOG.md` and, if it's a recipe already in `recipes/`, append a line to that recipe's "Cooking History" section too. Also decrement/remove used items from `groceries/INVENTORY.md`.
- When the user reports a grocery trip, add an entry to `groceries/PURCHASES.md` and add/update the corresponding rows in `groceries/INVENTORY.md`.
- Proactively flag items in `groceries/INVENTORY.md` that are near their use-by date and suggest a recipe to use them up.
- When suggesting new recipes to try, lean into the cuisines above and call out techniques that are new to the user, since skill-building is a stated goal.
- Whenever `meal-prep/*.md` or the `groceries/*.md` files change, run `node site/build.js` (or `npm run build`) to regenerate `docs/` before the user pushes — the GitHub Pages site is a mobile-friendly checklist view of these files. Checkbox state on the site (prep-day checklist, shopping list) persists only in each browser's local storage — it does not sync across devices and isn't reflected back into the `.md` files.
